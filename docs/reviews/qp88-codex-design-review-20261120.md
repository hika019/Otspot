**Q1. 恒等式は正しいが、「D-block Σ と同一」はコードの定義では誤り**

コードの符号規約に合わせ、制約を次のように書きます。

```text
A x + s = b
r_d = -(Qx + c + Aᵀy)
r_p = b - Ax - s
Y ds + S dy = r_c

Σ = Y⁻¹S = diag(s_i/y_i)
```

等式行では `s_i=ds_i=0`、`Σ_i=0` です。これは [compute_sigma_vec](/home/whisky/develop/Otspot-wt/pr84fix/otspot-core/src/qp/ipm_core/solver_loop.rs:135) の定義と一致します。

スラックを消去した正則化 Newton 系は、

```text
[ Q+ρI    Aᵀ       ] [dx] = [r_d,pmm            ]
[ A       -(Σ+δI)  ] [dy]   [r_p,pmm - Y⁻¹r_c  ]
```

です。したがって **双対側の負対角ブロックは `-D`、`D=Σ+δI`、`Σ=s/y`** です。[行列構築](/home/whisky/develop/Otspot-wt/pr84fix/otspot-core/src/qp/ipm_core/kkt.rs:454) がこれを直接示しています。

box 行 `a_t=±e_j` をさらに消去すると、

```text
d_t = 1/(s_t/y_t + δ_b)
dy_t = d_t(a_tᵀdx - r̃_p,t)

H_box = Q+ρI + Σ_t d_t a_t a_tᵀ
rhs_x = r_d,pmm + Σ_t a_t d_t r̃_p,t
```

となります。反復時の実装は `δ_b=0` なので、床処理が非活性なら `d_t=y_t/s_t` です。

一方、固定した `μ` に対する barrier は、

```text
s_t(x) = b_t-a_tᵀx
B_μ(x) = -μ Σ_t log s_t(x)

∇B_μ = Σ_t (μ/s_t)a_t
∇²B_μ = Σ_t (μ/s_t²)a_t a_tᵀ
```

です。ゆえに中心路上では確かに、

```text
y_t = μ/s_t  ⇒  μ/s_t² = y_t/s_t = Σ_t⁻¹
```

が成立します。

**一致する相手は、box 消去後の原始側 Hessian 寄与であって、消去前の D-block Σ そのものではありません。** 文書が別の記号規約として `Σ=y/s` を採用することは可能ですが、コードの `D=Σ+δI` と混用できません。

また、原始ブロックを `H` とすると、双対側 Schur 補元は、

```text
-D - A H⁻¹Aᵀ
```

です。文書の `AH⁻¹Aᵀ-D` は、このコードの符号規約では一致しません。

R3 の評価も分ける必要があります。

- C1 は box の `r_c` をゼロにし、**明示的な右辺項 `-a_t r_c,t/s_t` を実際に除去します**。
- ただし `μ/s²` の大きな曲率と、停留残差内の `μa/s` は残ります。
- したがって「右辺の中心補正を除去すれば収束する」という予測は過大ですが、「Hessian が中心路上で同じだから右辺項も除去されていない」という反証も成立しません。

なお、§3.2 の「自己共伴性」はここでは自己整合性との混同です。`μΦ` を任意の μ について「1-自己整合」と扱い、同じ減衰則を無条件に適用することもできません。

```text
dy_t   = d_t(a_tᵀdx-r̃_p,t)
ds_t   = -a_tᵀdx
```

は整合しています。Augmented／Schur の行列構築と後退復元は同じ係数関数を使い、box 行への `δ_b=0` の適用漏れも見つけられませんでした。

特に双対歩幅制限は、文書の式自体に符号誤りがあります。固定 μ なら、


であり、文書の `y(1+αds/s)` ではありません。

ところが実際に採用する更新は、

```text
y_new = μ_new/(s+αds)
```

です。`ds>0` の内側移動でこれは正ですが、旧来の線形双対更新に対する FTB は不要な制限を掛けます。例えば、

```text
s=y=1, ds=10, dy=-10
```

なら旧制限は `α≤0.0995`。従属更新の正値性には、この制限は不要です。これは小さな独立再現例になります。

Hessian も実装上は、

```text
d_t = 1/max(s_t/y_t, ε_machine)
    = min(y_t/s_t, 1/ε_machine)
```

です。上限は約 `4.5036e15`。例えば `μ=1,s=1e-9` では、真の曲率 `1e18` と一致しません。行列と後退復元は互いに整合しますが、barrier 勾配の微分とは不整合です。有限差分との比較で直接検出できます。

env の意味も注意が必要です。

```text

OTSPOT_QP88_AB=none         全 safeguard 無効、C1 は有効
OTSPOT_QP88_AB=delta        delta safeguard だけ無効
```

名前列挙は「有効化」ではなく「無効化」です。`OnceLock` のため同一プロセス内の env 変更も反映されません。C1 と legacy を切り替えるゲートではありません。

**Q3. 原始残差の停滞は確認できるが、原因の一意性は確認できない**

保存 trace の再集計結果は次のとおりです。反復数は複数 attempt を含む記録行数です。

| trace | 記録反復数 | `nrpE` 最小値 |
|---|---:|---:|
| 無接尾辞 | 405 | 0.9823 |
| c2 | 263 | 0.9995 |
| c3 | 263 | 0.9995 |
| c4 | 306 | 0.9992 |
| c5 | 306 | 0.9995 |

**実質的な停滞という記述は妥当ですが、「全反復で厳密に 1.0」「修復成分が存在しない」は強すぎます。**

例えば [c5 の52行目](/tmp/opencode/presolve_impl/spike_qgfrdxpn_c5.trace:52) は、

```text
rho=3.167e-5
delta=5.000e-8
dmaxb=4.347e15
nrpE=0.9995
```

であり、ρを小さくしても大きな残差が残ることは確認できます。

ただし、文書の数値説明には誤りがあります。

```text
μ=70, s=2e-6  ⇒ μ/s²=1.75e13
μ=70, s=2e-2  ⇒ μ/s²=1.75e5
```

したがって「余剰 2e-6～2e-2、μ≈70 ⇒ 1e14～1e18」はそのままでは成立しません。`s=5e-9` まで縮めば約 `2.8e18` になりますが、実装では前述の cap が作用します。

また trace は時点が混在しています。

- `mu`、`nrpE`、`dmaxb` は更新前。
- `muN`、`sminb` は更新後。
- `asb/asr/ayr` は更新後の状態に、更新前の方向を再適用して計算。

したがって同一行の `sminb` から `dmaxb=μ/sminb²` を検算したり、`asb` から実際の歩幅制約行を断定したりできません。

機構については、**巨大曲率と等式側の δ の組合せによる修復抑制**が、文書より正確な候補です。最小例として、

```text
h dx + dy = 0
dx - δdy = r
```

を厳密に解くと、

```text
dx = r/(1+δh)
```

です。`h=1e14,δ=8,r=1` なら `dx≈1.25e-15`。丸め誤差がなくても修復はほぼ止まります。しかし、

```text
δ=0 ⇒ dx=r
```

であり、Hessian が巨大でも等式修復は消えません。

これは次を意味します。

- 大きい `μ/s²` が停滞に関係する説明は合理的。
- しかし **barrier Hessian 自体が等式修復を必然的に失わせるわけではない**。
- 「ρを下げても直らない」だけでは、等式側 δ、方向の精度、歩幅制限を排除できない。
- 残差ノルムだけでは、方向に修復成分がないのか、歩幅が小さいのか、正則化項が残差を引き受けたのかを区別できない。

判別には、同一 iterate で以下を測る必要があります。

```text
e_E = A_E dx - δdy_E - r_p,pmm,E
predicted_r_E = r_E - α A_E dx
```

加えて、実装行列と真の barrier Hessian を使う独立解について、`A_E dx`、成分別後退誤差、実更新後の残差を比較します。

現段階の判断は、**設計上の困難は実在するが、実装依存の方向・更新問題が未排除であり、本質的不可能性の証拠にはならない**、です。

**Q5. 提案：実行可能性の修復と最適化を分離する box 消去法**

私なら、**実行可能性を優先する normal step と、実行可能性を保つ tangential step を分離した方式**を選びます。box は引き続き変数境界として保持し、境界行を KKT の明示行に戻しません。

設計の要点は以下です。

1. **初期・停滞時は、barrier 曲率に依存しない実行可能性修復を行う。**

   原問題の線形制約違反を、行スケール付きで最小化します。

   ```text
   V(x) =
     1/2 ||W_E(A_E x-b_E)||²
     + 1/2 ||W_I max(A_I x-b_I,0)||²

   subject to l≤x≤u
   ```

   これは box 制約付きの凸・区分二次問題です。bound active-set 法で解き、`μ/s²` を修復方向の計量に使いません。`AᵀA` を明示的に形成せず、実制約の残差変数を使う疎な拡大系で処理します。

   活性境界は変数固定として扱うので、系は基本的に `n_free+m_real` 以下です。実行可能性修復の段階から巨大 barrier 曲率に支配される循環を避けます。

2. **等式の実行可能性を得た後は、等式を硬い制約として保持する。**

   最適化側の Newton 系は概念的に、

   ```text
   [ H          A_Eᵀ ] [dx ] = [r_d]
   [ A_E        0    ] [dλ_E]   [r_E]
   ```

   とし、実不等式の通常のブロックを併設します。実行可能点では `A_E dx=0` です。

   等式正則化が数値上必要な場合でも、「正則化した系を解けた」だけで受理せず、元の等式で `A_E dx-r_E` を検証します。Q3 の `1/(1+δh)` による修復抑制を、見えないまま受け入れません。

3. **μ は観測された相補積平均から切り離し、明示的な継続パラメータにする。**

   固定 μ の内部問題を、残差・中心性が所定水準に入るまで解いてから μ を下げます。box は常に、

   ```text
   s_t=b_t-a_tᵀx
   y_t=μ/s_t
   ```

   と再計算します。従属 box 双対を FTB の対象から外し、元の境界を守る primal FTB と、固定 μ の merit/filter 判定で受理します。

   これにより、μ₀だけ変更して直後に実制約の `sy` から70へ戻すスパイクの不整合を避けます。

4. **巨大曲率は cap せず、対称スケーリングして解く。**

   例えば `T_jj=1/sqrt(H_jj)` を基本に、

   ```text
   K̂ = diag(T,R) K diag(T,R)
   ```

   として因子分解し、元の座標で後退誤差を検証します。スケーリングは conditioning の改善策であり、実行可能性修復の代わりにはしません。

この設計でも `μ/s²=y/s` は残ります。恒等式を回避する必要はありません。**回避するのは、初期実行可能性の修復まで巨大 barrier 曲率と軟らかい等式制約に任せる構造**です。

破綻を検出する試験は、次のように具体化できます。

| 試験 | 検出する失敗 |
|---|---|
| Q3 の一変数等式例で h を広範囲に変更 | 巨大曲率による等式修復の消失 |
| barrier 勾配の有限差分と行列・`dy` の比較 | cap、符号、転置、微分不整合 |
| `ds>0` の内側移動例 | 不要な box dual FTB の残存 |
| qgfrdxpn／qshell／9002 の行別残差・予測減少・実減少記録 | 修復方向はあるが歩幅で失う／方向自体が不良、の区別 |
| dt の既存 fixture、手計算解 `(5,5), obj=-50` | 相補性振動と誤った成功判定 |
| LASSO 3件・ill-scaled 2件の既存予算 | 修復 phase／μ継続の過剰コスト |
| CONT-300、同条件で peak RSS・wall を再測定 | 別の因子分解によるメモリ利益の喪失 |

厳密内点が存在しない問題では、固定変数や強制活性面の同定が必要です。この部分を省いて barrier phase へ移す設計にはしません。また、系の次元維持だけで RSS −75% を保証することはできません。fill-in を含めて、既存の 412 MiB アンカーに対する実測が採用条件です。

**総合判定：不成立結論＝一部のみ正しい。**

- スパイクの停滞・予算超過は、採用を見送る根拠になります。
- `μ/s²=y/s` は正しいものの、D-block の同定と、それを使った不成立の論証は誤っています。
- δ二重減衰、従属双対への旧歩幅制限、曲率 cap、未実装の barrier 受理判定により、設計候補全体の反証にはなっていません。
- dt の「obj=4.0 成功」は証跡と既存オラクルが一致せず、再確認が必要です。

したがって、**このスパイクをマージしない判断は支持しますが、§9.2 を確定した真因として次の設計の前提にすることは勧めません。**
